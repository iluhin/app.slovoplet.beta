# Выпуск beta-версий и компонентов

[Главная beta](../README.md) · [Формат манифеста](../ota/README.md) · [Проверки](VERIFICATION.md)

## Сначала выбрать тип изменения

| Что меняется | Что выпускать |
|---|---|
| Разметка, JavaScript, CSS, изображения, встроенные веб-данные | Новая подписанная версия компонентов |
| Java-классы, возможности моста, разрешения, Android-ресурсы или иконка | Новый подписанный APK оболочки |
| Только справка этого репозитория | Обычный коммит документации, без смены версии приложения |

Beta живёт в main отдельного репозитория app.slovoplet.beta.
Стабильные выпуски и история остаются в app.slovoplet.

Исправленные APK используют пакет com.iluhin.fiveletters.beta и origin:
https://raw.githubusercontent.com/iluhin/app.slovoplet.beta/main/ota/
Идентификатор APK проверяется по скомпилированному AndroidManifest.
[Отличия от первоначальных con-сборок](MIGRATION.md).

## Что хранится в публичном репозитории

- `beta-dist/` — готовые подписанные APK, ZIP снимков и манифесты для выпуска.
- `ota/manifest.json` — подписанный текущий указатель beta-канала.
- `ota/manifest-<версия>.json` — подписанные снимки.
- `ota/blobs/<sha256>.bin` — неизменяемые компоненты.
- `releases/beta-v*.md` — заметки для тестировщика.

Основной код и ключи подписи не находятся в этом публичном репозитории.
Workflow **не компилирует и не подписывает** APK или компоненты: он публикует
уже подготовленные артефакты после проверки контрольных сумм.

## Порядок выпуска компонентов

1. Подготовить **полный** снимок веб-части на основе нужной версии игры. Манифест
   перечисляет все файлы, а не только изменённый: совпавшие файлы переиспользует загрузчик.
2. Назначить новую версию и ревизию, указать `channel: beta`, пакет
   `com.iluhin.fiveletters.beta` и совместимые сборки оболочки.
3. Для каждого файла вычислить SHA-256 и размер. Новое содержимое получает новый
   blob с именем по хешу. Опубликованные blobs не перезаписываются.
4. Подписать **точные UTF-8-байты payload** доверенным ключом владельца и собрать
   JSON-обёртку с Base64-полями `payload` и `signature`. Обычной правки JSON недостаточно.
5. Проверить подпись, хеши, размеры, совместимость, откат и работу новой веб-части.
6. Добавить все новые blobs и снимок манифеста, затем переключить `ota/manifest.json`.
   Предпочтителен один коммит: манифест не должен указывать на ещё не опубликованные файлы.
7. Создать отдельный **предварительный** beta-релиз с заметкой, снимком манифеста,
   архивом компонентов и контрольными суммами. Не отмечать его стабильным Latest.
8. Проверить переход именно из предыдущего APK/набора компонентов, а не только
   чистую установку целевой версии. Повторить запуск без сети.
9. Обновить таблицу текущих версий в README, историю, протокол проверок и инструкцию теста.

Если ревизия неудачна, публикуется **следующая** исправленная ревизия. Загрузчик
блокирует повторное применение той же неудачной версии; перезапись старого blob
или изменения под прежней подписью не являются способом исправления.

## Порядок выпуска оболочки APK

Собрать приложение из закрытого исходного проекта с beta-пакетом и новым
`versionCode`, встроить совместимые компоненты, подписать прежним ключом.
Проверить чистую установку, обновление предыдущей beta и восстановление данных.
APK выкладывается в beta-релиз отдельно от веб-компонентов.

Смена доверенного ключа OTA требует обновления закреплённого ключа в APK и
отдельного плана перехода. Правка одного публичного PEM-файла не меняет доверие уже установленных приложений.

## Текущий workflow публикации

[Publish beta 3.1](../.github/workflows/publish-beta.yml) работает только
в main этого beta-репозитория. Проверяет пакет/версии/сертификат APK,
подписи и хеши манифестов, содержимое APK/ZIP, четыре скомпилированных XML.
Публикует только новый beta-v3.1.0: предыдущие r2-релизы не перезаписываются.

Указатель ota/manifest.json ведёт на 3.1; снимки 3.0/3.0.1 сохранены.
Для следующего выпуска осознанно обновляются версия, артефакты и проверки.
Публикатор сам не компилирует и не подписывает приложение.

APK 3.1 собран с полной компиляцией новых XML через aapt2 и генерацией R до Java/Dex.
Старый резервный способ переиспользования ресурсов 1.4 не используется.
Новые Android-виджеты не могут приехать веб-компонентами старой оболочки.

## Два пространства

- app.slovoplet — стабильная документация, APK и история 1.4–2.7.2.
- app.slovoplet.beta — документация beta, версии оболочки и компонентов, предварительные релизы.
- Старая ветка app.slovoplet:beta — только совместимость выпущенных APK и ссылка на новое место.

Стабильные workflow публикации и выкладки Wiki в этот репозиторий не перенесены.
Справка доступна файлами wiki/; опубликованные beta-релизы принадлежат этому
репозиторию и не попадают в список стабильных выпусков.

Перед публикацией запускается [.github/scripts/verify_beta.py](../.github/scripts/verify_beta.py): идентификатор и версии из бинарного APK, сертификат владельца, подписи манифестов, origin и хеши компонентов. Требуются Android SDK aapt2/apksigner и OpenSSL.
