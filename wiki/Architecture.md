# Как устроено обновление beta

[Справка beta](Home.md) · [Формат OTA](../ota/README.md) · [Порядок выпуска](../docs/RELEASING.md)

## Кто за что отвечает

| Часть | Задачи | Способ обновления |
|---|---|---|
| Android-оболочка | WebView, хранение снимков, проверка подписи, загрузка и переключение файлов | Новый APK |
| Веб-компоненты | Поле, клавиатура, экраны, логика клиента, стили и ресурсы | Подписанный beta-канал |
| Игровой сервер | Профили, онлайн-партии, слово дня, рейтинг и настройки | Обновление серверного кода отдельно |

Веб-часть открывается под прежним HTTPS-адресом игры. Оболочка перехватывает
запросы к своим ресурсам и отдаёт один выбранный локальный снимок. Серверные
запросы и сессия продолжают работать с игровым сервером.

## Цикл обновления

1. После успешного запуска исправленный beta-APK запрашивает ota/manifest.json из app.slovoplet.beta:main; [подробности переноса](../docs/MIGRATION.md).
2. Оболочка проверяет RSA/SHA-256-подпись закреплённым в APK ключом, затем канал,
   пакет, ревизию, совместимость и список файлов.
3. Файлы, чьи SHA-256 совпали, используются повторно. Остальные загружаются по
   адресам `blobs/<sha256>.bin` и проверяются по размеру и хешу.
4. Полный новый набор сохраняется в отдельной папке внутренней памяти. До
   переключения игра использует текущий снимок.
5. По кнопке после партии или при новом запуске указатель переключается на
   подготовленную версию. WebView получает её ресурсы без смешивания версий.
6. Успешно запущенная игра подтверждает версию. Она становится рабочей для следующих запусков.

## Откат

Если запуск не подтверждён за 30 секунд либо приложение закрылось до
подтверждения, загрузчик возвращает последнюю подтверждённую версию.
Повреждённый подготовленный манифест или компонент тоже не заменяет рабочий
снимок. Если он повреждён, проверяется предыдущий подтверждённый снимок;
встроенная в APK версия остаётся последним запасным вариантом.

Неудачная ревизия блокируется от повторного автоматического применения.
Для исправления публикуется новая подписанная ревизия.

## Границы текущей реализации

- Проверка и загрузка идут в фоновом потоке **при запущенной игре**. Периодической загрузки при закрытом приложении нет.
- Загрузка сама не перезапускает партию. Ручное применение во время партии блокируется интерфейсом.
- Статус показывает этап; счётчики файлов/байтов появляются по завершении, без живой полосы прогресса.
- Не обновляются через этот канал Java-классы, DEX и нативные библиотеки.
- ZIP в релизе — снимок для просмотра. Приложение скачивает отдельные компоненты, а не весь архив.
- Схема подписи проверена автоматически; поведение реального Android/WebView ещё требует [проверки устройством](../docs/TESTING.md).

[Подтверждённые проверки и оставшиеся задачи →](../docs/VERIFICATION.md)

Новый APK 3.1 устанавливает нижнюю границу компонентов 30100: старый OTA-кэш
не скрывает встроенную версию, а более новые подтверждённые компоненты сохраняются.
[Виджеты](../docs/WIDGETS.md) используют локальные снимки без фонового опроса сервера.
